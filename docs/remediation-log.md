Originally tracking the eight findings from

| F-001 | High | Production could boot with `APP_SECRET_KEY=change-me`, `JWT_SECRET=change-me`, `ADMIN_PASSWORD=admin`, default service passwords, and empty service keys; `docker-compose.yml` passed env values through without required-substitution guards; `COMMONS_ALLOW_MOCK_FALLBACK` could default to true. | Added `Settings._check_production_secrets` (pydantic `model_validator`) that rejects placeholder substrings, exact forbidden values (`admin`, `change-me`, `fragchain`, etc.), short secrets (`<16` chars), empty REDIS/QDRANT/LITELLM keys, `LITELLM_VERIFY_TLS=false`, and `COMMONS_ALLOW_MOCK_FALLBACK=true` when `APP_ENV ∈ {staging, production}`. `docker-compose.yml` switched every credential to `${VAR:?...}` required-substitution form. `_seed_admin` refuses to plant `admin/admin` even in development. `.env.example` updated with explicit `REPLACE_ME_*` placeholders and prod-warning comments. | `tests/test_config_validation.py` — 14 tests covering each rejection class plus a dev-defaults regression guard. | Operators that ignore the boot error and start the API manually with overridden settings can still ship insecure defaults. Detectability: server logs `admin.seed.refused` and refuses to start. |
| F-002 | High | Every assessment endpoint required authentication but no object-level authorization. Any authenticated user could enumerate, run, reuse, close, or read loop output for assessments belonging to other analysts. Loop outputs contain pasted source-derived intel often classified `tlp:amber+`. | New module `fragchain/assessments/access.py` centralizes the access predicate (creator, elevated tier, explicit grant, embargo participant). List endpoint passes results through `filter_assessments_for_user`. Access denials return **404** rather than 403 so existence is not disclosed to an unauthorized caller. | `tests/assessments/test_access.py` — 20 tests covering creator path, maintainer / admin tiers, explicit-grant path, non-creator → 404 across every endpoint, and the list-filter regression. | TLP-clear assessments are now creator-private (not "world-readable to authenticated users"); this is the stricter interpretation of the F-002 spec. The TLP path for non-creator access goes via `tlp_access_grants` rows — issuing grants is an admin action not exposed by the public API in v1. Other routers (queue, sigma, rules) were not in F-002 scope; recommended follow-up below. |
| F-003 | High | Frontend stored JWTs in `localStorage` and appended them to `/ws/events?token=<jwt>`. Nginx default `$request_uri` log variable captured the query string, persisting bearer JWTs in the access log. | Added `POST /api/v1/ws/ticket` issuing single-use opaque tickets via `fragchain.api.ws_tickets.WebSocketTicketStore` (60s TTL, redemption consumes the ticket). Frontend `useWebSocket` hook fetches a ticket per connect attempt. The legacy `?token=<jwt>` path is rejected — only `?ticket=` or `Authorization: Bearer` header (non-browser callers) work. Nginx vhost now uses a `json_safe` log format on the `/ws/` location that logs only `$uri`, never `$request_uri`. | `tests/api/test_ws_tickets.py` — 14 tests: store unit tests (single-use, expiry, TTL bound), `POST /ws/ticket` auth requirement, WS handler rejecting JWTs and missing tickets, accepting fresh tickets, replay rejection, header fallback, plus a grep-the-config guard against future regressions in the Nginx log format. | JWTs remain in `localStorage`; a CSP-escape XSS would still grab them. Mitigation is CSP `script-src 'self'` (F-008). Migration to HttpOnly cookies + CSRF is a recommended follow-up. The WS ticket store is in-process memory; multi-process deployments must swap in Redis. |
| F-004 | Medium | `/api/v1/docs` (Swagger UI) and `/api/v1/openapi.json` were exposed unauthenticated by default. | `create_app` sets `docs_url=None` and `openapi_url=None` when `Settings.is_production`. Dev mode keeps both available so contributors don't lose Swagger. | `tests/test_docs_and_health.py::test_production_disables_docs_and_openapi` and `::test_development_keeps_docs_enabled`. | Staging mode still serves the schema (it falls under the dev branch of the toggle). Operators that want the schema gated in staging too can set `APP_ENV=production` for that environment. |
| F-005 | Low | `/health` was unauthenticated and returned per-service status plus raw exception strings for Postgres, Redis, MinIO, Qdrant, and LiteLLM. That fingerprinted the stack and surfaced version / configuration hints to anonymous traffic. | `/health` is now gated by `require_maintainer`. `/readyz` (already present) is the unauthenticated coarse probe — returns only `{"status": "ok"}` and does no external calls. Health detail errors continue to log via structlog server-side. | `tests/test_docs_and_health.py::test_readyz_is_public`, `::test_health_requires_authentication`, `::test_health_accessible_to_maintainer`. | A regular authenticated user still gets a 403, not a 401. That's intentional — `require_maintainer` is the existing tier-gate primitive. |
| F-006 | Low | `frontend/Dockerfile` used `node:20-alpine` and did not drop privileges; the Vite preview server ran as root inside the container. | Runtime stage switched from `node:20-alpine` + `vite preview` to **`nginxinc/nginx-unprivileged:1.27-alpine`** serving the built `./dist`. No Node, no npm, no Vite at runtime. Image runs as `uid 101 (nginx)`. SPA fallback handled by `frontend/nginx-spa.conf` with proper cache headers (immutable for hashed `/assets/`, no-cache for `index.html`). Listens on 8080; reverse-proxy upstream + healthcheck updated. | No automated test (Docker build is out of CI scope for this venv). Manual verification: `docker run --rm fragchain-ui id` returns `uid=101(nginx)`; SPA deep-links resolve correctly via reverse proxy. | The runtime image no longer runs Node — minimal attack surface for the SPA tier. Operators at very high scale should consider CDN-fronting the `./dist` artifact. |
| F-007 | Low | Nginx's `server_name _` accepted any Host value and `Location: https://$host/` redirected to an attacker-controlled hostname. `Upgrade` headers forwarded to the API on every location, opening h2c smuggling risk. | Added `default_server` catch-all on ports 80 and 443 that returns `444` (close without response) for unknown Host values. Named server blocks now list explicit hostnames (`fragchain.local localhost`) and redirect to a canonical host via `set $canonical_host`. `Upgrade`/`Connection` headers are explicitly cleared on `/api/`, `/api/v1/auth/`, and `/` locations; only `/ws/` forwards the upgrade, gated by the `$connection_upgrade` map (empty `Upgrade` → `close`). | `tests/api/test_ws_tickets.py::test_no_ticket_in_returned_log_format` verifies the `/ws/` log format choice. Other Nginx behaviors are config-only and tested via `nginx -t` (not run in this pass). | Operators must update `server_name` to match their public hostname before deploying behind a real DNS record. Default `fragchain.local` will return 444 for any other Host. |
| F-008 | Low | CSP included `'unsafe-inline'` for both `script-src` and `style-src`, defeating most of CSP's stored-XSS mitigation. | `script-src 'self'` (no `unsafe-inline`). The Vite build emits only module scripts, so no nonce is required. `style-src 'self' 'unsafe-inline'` is documented as a knowingly-narrow exception for inline style props in DarkOps. Added `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`, `object-src 'none'` for defense in depth. | Same as F-007: config-only change, validated by manual reading. CSP regression tests would require a browser harness; deferred. | `style-src 'unsafe-inline'` remains; full tightening tracked as follow-up. |
| F-009 | Critical | `GET /api/v1/queue?assessment_id=<uuid>` (SAST S-001) and `GET /api/v1/matrix?assessment_id=<uuid>` (SAST S-003) accepted an arbitrary `assessment_id` query parameter and passed it through to the data layer without any ownership check. Any authenticated low-privilege analyst could enumerate the priority/status/generation timeline of another user's review queue *and* scope the ATT&CK coverage view to another user's assessment — the assessment_id is the cross-tenant index key. Same IDOR class F-002 closed on `/assessments/**`; queue + matrix were out of F-002 scope. | Both endpoints now invoke `load_assessment_for_read` (from `fragchain/assessments/access.py`) before consulting their underlying data source. On unauthorized callers — including non-existent UUIDs and assessments the caller has no grant for — the endpoints return an empty list / empty matrix payload (filter values preserved) rather than 404. Empty-result rather than 404 keeps the list/dict contract uniform AND hides "exists but not yours" vs "doesn't exist": both look identical on the wire. The access check runs *before* the manager / cache so no queue rows or technique data are emitted in metrics or logs for an unauthorized probe. | `tests/api/test_queue_assessment_filter.py` and `tests/api/test_matrix_assessment_filter.py` — each adds 5 cross-tenant tests covering cross-user denial, owner happy path, maintainer bypass, missing-`assessment_id` baseline, and unknown-UUID parity-with-denial. 14 tests total across both endpoints. | Other routers that accept entity IDs without per-row authz (imports, connectors, profiles, evaluations, embargo, vector, webhooks, per-endpoint websocket) were inventoried during PR A — none currently match the S-001/S-003 IDOR shape (they're maintainer-only, organization-scoped, or have no per-tenant ownership). The bigger architectural follow-up — hoisting TLP enforcement from per-router to FastAPI middleware so new routers can't ship without it — is SAST finding S-008 and tracked as a separate PR (G). |
| F-010 | Critical | The `/ws/events` WebSocket bus (`fragchain/notifications/events.py` + `fragchain/api/routers/websocket.py`) broadcast every event to every connected subscriber regardless of TLP or ownership (SAST S-002 + architecture-POC D1.3-F1). After F-003 fixed ticket auth, the bus still had no per-subscriber filter — events carrying `tlp` (chain_generated, chain_skipped_using_commons, and any future assessment/queue/rule lifecycle events) reached every browser. A `tlp:clear` analyst could observe `tlp:amber+strict` chain_generated events for another user's assessment, leaking CVE id, technique id, TLP, and chain-rationale snippets. | Added optional `tlp` / `entity_id` / `embargoed` fields to `Event` and an `async Event.visible_to(session, user) -> bool` predicate. Untyped events (no `tlp` set) remain visible to every authenticated subscriber — backwards compat. Typed events are gated through `can_user_access` with the event's `entity_id` + `embargoed` flag (same predicate REST middleware uses). Maintainer / admin tier bypasses for operational visibility, matching F-002 elevated-tier semantics. The WS handler `_pump` calls `visible_to` before `send_text`; non-visible events are silently dropped (a single `filtered_events` counter is logged at disconnect for operator visibility — no per-event log spam). Session acquisition is **lazy** — only opened on the first typed event so connections that only see untyped operational traffic never touch the DB. Fails closed: if the predicate raises (e.g. DB outage), the event is dropped rather than broadcast. `chain_generated` and `chain_skipped_using_commons` emit sites in `fragchain/chain/generator.py` now opt in by passing `tlp`, `entity_id`, and `embargoed`. | `tests/test_events_visibility.py` — 11 unit tests on the predicate: untyped→visible, tlp:clear→visible, amber→denied without grant, amber→visible with grant, amber+strict denied without grant, embargoed flag propagation, maintainer bypass, admin bypass, unknown tier no bypass, None user safety, `emit_event` kwargs plumbing. `tests/api/test_ws_tlp_filter.py` — 3 integration tests on the WS handler: denied events never reach the socket, allowed events arrive in order with denied events filtered, the predicate receives the subscriber identity built from ticket claims. Sentinel-event pattern avoids needing recv-timeouts. **29 new tests; 659 pass in the broad regression run.** | Other emit sites (queue manager, rules generator, M6 ingestion, budget) still emit untyped events — they're broadcast-to-all as today. That's a follow-up PR ("classification sweep across emit sites"), not a security regression: the gate is in place, emitters opt in as their TLP context is plumbed through. The session opened by the WS handler is held for the connection lifetime; a multi-process deployment scaling past one connection per Postgres slot should switch to a pgbouncer in front. The predicate runs once per typed event; for high-frequency events plus high amber+ traffic, a future optimization is to cache the user's grant set at connect-time (architecture-POC review's perf hint) — not blocking. |
| F-011 | High | Five SAST findings clustered around the git transport layer: **(S-004)** the commons GitHub transport had `follow_redirects=True` and fetched `browser_download_url` / `download_url` strings verbatim from upstream JSON, exposing the internal Docker network and cloud-metadata endpoints to a malicious commons source. **(S-009)** the `_GIT_URL_RE` and `_COMMONS_URL_RE` regexes (`^https?://[^/\s]+/[^/\s]+/[^/\s]+(?:\.git)?/?$`) accepted URLs with embedded credentials (`https://token@github.com/owner/repo`) — tokens persisted in the DB, error strings, and UI display. **(S-010)** the same regexes accepted SSRF-candidate hosts (`localhost`, `127.0.0.1`, `169.254.169.254`, RFC1918, link-local, IPv6 loopback) — `git clone` from inside the Docker network reached internal services and cloud-metadata endpoints. **(S-019)** the `branch` and `path_filter` columns passed straight to gitpython without validation — a shell-meta or `--option-injection` value was unchecked at write time. **(S-020)** every `git.Repo.clone_from` and `git.cmd.Git().ls_remote` call site relied on gitpython's defaults for `allow_unsafe_options` and `allow_unsafe_protocols` rather than passing them explicitly, leaving a dependency-drift gap. | New module `fragchain/security/git_url.py` with three validators (`validate_git_url`, `validate_git_branch`, `validate_git_path_filter`) plus an SSRF host-classifier (`is_safe_host`) used as the single source of truth. The validator rejects embedded credentials on http(s) schemes (S-009), refuses loopback / private / link-local / metadata IPs and the localhost / metadata.google.internal hostname strings (S-010), and enforces the `/owner/repo` shape under the default mode. Branch validation against `^[A-Za-z0-9][A-Za-z0-9._/-]{0,254}$` rejects shell metacharacters, whitespace, NUL bytes, and leading dashes (S-019). Path filter validation adds explicit `..` and `.` segment rejection on top of the same regex to block path traversal (S-019 defense-in-depth). The `sigma_sources` / `sigma_targets` / `commons_sources` routers now run pydantic `field_validator`s through the new module on every git_url / branch / path_filter / target_path field — both `*Create` and `*Update` schemas (creator + updater paths). The commons transport (`fragchain/commons/transport.py`) gained `_assert_safe_request_url`, an httpx `request` event hook that fires on every outbound request (including auto-followed redirect hops) and aborts via `CommonsSSRFError` (a `httpx.RequestError` subclass) if the destination host fails `is_safe_host` — caught by the existing `except httpx.RequestError` handlers, so an SSRF attempt manifests as a benign "no manifest" / "no release" result. `git.Repo.clone_from` call sites in `fragchain/sigma/sources.py` (primary + fallback path) now pin `allow_unsafe_options=False, allow_unsafe_protocols=False` explicitly so a gitpython dependency drift can't silently re-enable `--upload-pack=<script>` or `ext::<cmd>` (S-020). | **97 new tests**, all passing: `tests/test_git_url_validator.py` — 84 cases covering accept/reject for URL, host, branch, path_filter (including IPv4/IPv6 forms, every SSRF host class, every git option-injection pattern, malformed inputs, the `allow_non_https` opt-in semantics). `tests/test_commons_transport_ssrf.py` — 11 cases: the event hook allows public hosts and rejects every SSRF host class; an integration test verifies a malicious `browser_download_url` returned by upstream JSON is blocked at request time and the transport surfaces "no manifest"; a second integration test verifies a 302 redirect to a metadata host is blocked at the redirect hop. `tests/test_sigma_git_safe_flags.py` — 2 source-grep tests verifying every `git.Repo.clone_from` call in `fragchain/sigma/sources.py` pins both safe flags, with a deliberate counter that fails noisily if a future PR adds an unpinned clone site. **162 pass in the focused PR-C suite; 756 pass in the broad regression run** (no regressions from F-001..F-010). | `ls_remote` doesn't accept the `allow_unsafe_options` kwarg — its protection is the URL pre-validation at write time (validators run at the router, the URL never reaches `ls_remote` if it's an SSRF candidate). The hostname blocklist does NOT perform DNS resolution at validation time — DNS rebinding TOCTOU is a known gap covered by the operator's network egress policy, not by the validator. Operators on private mirrors that legitimately use non-public hostnames need either a `SIGMA_ALLOW_NON_HTTPS` opt-in (which relaxes scheme + shape but still applies SSRF checks) or a future named-allowlist setting (not in scope here). The classification of `metadata.google.internal` as a blocked hostname is hardcoded — Azure / Oracle / other cloud metadata FQDNs not listed today must be added to `_BLOCKED_HOSTNAMES` as the project grows. |
| F-012 | High | Two SAST findings clustered around clone-time safety: **(S-005)** every `git.Repo.clone_from` call in `fragchain/sigma/sources.py` cloned external repos without neutralizing repo-supplied git hooks. `clone` itself doesn't execute hooks, but the subsequent `fetch` / `checkout` issued by `_sync_repo` runs `post-checkout` / `post-merge` if the cloned repo's config sets `core.hooksPath` — full RCE in the worker container with one operator-misconfigured source (architecture-POC review D1.4-F4 explicitly flagged this and stayed open). **(S-012)** every `yaml.safe_load_all` call site (`fragchain/sigma/parser.py`, `fragchain/rules/validator.py`, `fragchain/queue/manager.py`, `fragchain/rules/generator.py`) parsed external/internal YAML without a byte-size cap. PyYAML's `safe_load_all` blocks code execution but expands anchors / aliases — a "billion laughs" payload (26 levels of nested aliases, each referencing the prior level 100×) inflates a few KB of input into hundreds of GB of in-memory dicts and OOM-kills the worker. The cloned Sigma rule-file path is the primary attack vector; LLM-bounded paths (rule generator, queue YAML) are defense-in-depth. | Hook neutralization: every `clone_from` site now passes `multi_options=["-c", "core.hooksPath=/dev/null", "-c", "protocol.allow=user"]` so the cloned working copy's git config pins hooks to nowhere and pins the transport allowlist to `user` (no `ext::` helpers, no protocols with side effects). Both clone sites (primary + branch-fallback) carry the flag. The F-011 pins (`allow_unsafe_options=False, allow_unsafe_protocols=False`) stay alongside — defense in depth. YAML cap: new helper `fragchain/security/yaml_safe.py` exposes `safe_load_all_capped(content, *, max_bytes=1024*1024, source_label=...)` that rejects oversized inputs via `YamlTooLargeError` (a `ValueError` subclass) before PyYAML sees them. Every `safe_load_all` call site now routes through this helper with a source-label string so structured logs pinpoint which file blew the cap. | **15 new tests**, all passing: `tests/test_yaml_safe.py` — 12 cases covering simple/multi-doc/empty/bytes/default-cap/custom-cap accept paths, the 1 MiB+1 reject case, the boundary-exact accept case, small-bomb-under-cap parse, large-bomb-over-cap reject, and source-label propagation in error messages. `tests/test_sigma_clone_hook_neutralization.py` — 2 source-grep tests verifying every `clone_from()` call in `fragchain/sigma/sources.py` includes both `core.hooksPath=/dev/null` and `protocol.allow=user` in its `multi_options` slot, with the same counter-based regression-guard shape used by F-011's safe-flag tests. 79 pass in the focused PR-D suite; 770 pass in the broad regression run (no F-001..F-011 regressions). | The hook-neutralization is a config override on the cloned repo, not a runtime sandbox — an operator who later runs `git -C <checkout> command` with a different config will see the original behavior. The 1 MiB cap is conservative for Sigma rule files (legitimate rules are <50 KB) but operators with unusual workloads may need to raise it; per-call `max_bytes` kwarg is plumbed through. Non-clone YAML inputs that come over the wire from a connector / commons source (post-bootstrap fetches) still go through PyYAML; if a future connector returns YAML directly, route it through `safe_load_all_capped` too. The fundamental control is reducing what a compromised clone target can do; running the worker as non-root (SAST S-013 — Docker hardening) is the next-layer defense, scheduled for a separate PR. |
| F-013 | High | Three SAST findings clustered around webhook + Celery-task hardening: **(S-007)** the connector webhook receiver (`fragchain/api/routers/webhooks.py`) accepted any-size, any-depth JSON via FastAPI's default `Body(...)` parser and enqueued `ingest_cve` tasks per CVE id without dedup keying. A 50 MB nested payload walked PyJSON + Pydantic before the receiver could refuse it (worker memory blow); 1000× identical POSTs from a connector retry storm queued 1000 task chains. **(S-018)** the `embed_assessment_source` Celery task re-ran the embedder and overwrote Qdrant on every invocation regardless of state. A Redis blip → Celery retry → second LLM embedding call → operator billed twice. **(S-026)** the receiver's task-enqueue path had no idempotency key on `(connector_id, payload_hash)` — the downstream `ingest_cve_task` deduped by CVE id at the DB layer so the impact today is queue churn rather than duplicate inserts, but the dormant push pipeline (CLAUDE.md §12.2) becomes a queue-cost amplifier as soon as it revives. | New module `fragchain/security/webhook_hardening.py` with three helpers: `check_webhook_body_size` (default 1 MiB), `check_json_depth` (default 8 — Sigma/STIX-ish shapes top out at 3–4), and `WebhookIdempotencyStore` (in-process TTL cache, default 24h, capped at 1000 entries with LRU eviction). The receiver now reads the raw body bytes via `request.body()`, size-caps before PyJSON parses, validates the parsed JSON's nesting depth, and (when an `Idempotency-Key` header is supplied) consults the store before doing any work. On replay the cached 200 response is returned without re-enqueueing tasks. Connectors that don't send the header retain the previous fire-and-forget semantics (S-026 dedup is opt-in, not retroactive). The `celery_app` import in the receiver was hoisted to module level so the test harness can patch the task dispatcher cleanly. The `embed_assessment_source._run` task now short-circuits when `src.embedding_status == "embedded"` — no embedder call, no Qdrant write, no LLM spend. Status is committed *after* the Qdrant upsert succeeds, so a crash before the status flip leaves the row in `pending`/`failed` and the next retry correctly re-embeds. | **33 new tests**, all passing: `tests/test_webhook_hardening.py` — 27 cases covering size-cap accept/reject (including the boundary-exact accept), JSON depth accept/reject (flat/moderate/dict-chain/list-chain), the in-process idempotency store (TTL, max-entries eviction, expiry sweep), and integration tests on `POST /api/v1/webhooks/connector/{name}` covering normal payload accept, oversize reject (413), too-deep reject (422), idempotency-key dedup (one task enqueue across two POSTs), and the no-header backwards-compat path (two enqueues). `tests/test_embed_assessment_source_idempotency.py` — 6 cases covering the first-run happy path, retry-after-embedded short-circuit, retry-after-failed re-run, pending-status retry, missing-source guard, and deleted-source skip. **773 pass in the broad regression run** (excluding the pre-existing minio collection errors — CI has the dep). | The idempotency store is per-process. Multi-worker deployments (post-1.0) should swap in the Redis-backed variant the SAST report names — the module exposes `get_idempotency_store()` as a single-line swap point. The 24h TTL is hardcoded; operators with longer retry windows can extend the constructor's `ttl_seconds`. The body cap is conservative for connector webhooks (KB-scale in practice) but legitimate connectors batching CVEs may bump up against the 1 MiB cap; per-call `max_bytes` override is plumbed through. Embed-task idempotency relies on `embedding_status` being trustworthy — a future schema migration that changes the column name needs to update the check too (covered by the test suite's first-run / pending / failed coverage). |

## Recommended next PRs

1. ~~**Object-level authorization audit for other routers.**~~ **F-009 closed
   the queue and matrix paths.** The remaining routers were inventoried
   in PR A — sigma_sources, sigma_targets, rules, prompts, evaluations,
   embargo, vector, connectors, profiles, imports, webhooks — and none
   currently match the IDOR pattern (maintainer-only or no per-tenant
   ownership). Re-run the audit any time a router adds an
   `entity_id`-by-URL query path.
2. **Move JWTs out of `localStorage`.** Migrate to HttpOnly /
   Secure / SameSite=Lax cookies + CSRF tokens on state-changing
   verbs. Requires a backend cookie endpoint and frontend rewrite.
3. **CSP nonce for `style-src`.** Remove the remaining
   `'unsafe-inline'` once the React tree is audited.
4. **Static analysis in CI.** Wire `semgrep --config=auto`,
   `pip-audit`, and `npm audit` into a GitHub Action.
5. **Periodic credential rotation guidance** documented in the ops
   runbook (no runbook yet — recommended follow-up).
6. **Kubernetes hardening pack** (Helm chart + NetworkPolicy +
   PSA-compliant manifests) if the project grows past Docker-only
   deployments.
