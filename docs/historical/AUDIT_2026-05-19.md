# FragChain audit — 2026-05-19

## Executive summary

- **Active flow (assessment-centric) is fully shipped.** Plans A/B/C and Phase A completion all land in code — every concrete design claim verified mechanically resolved to a column, endpoint, service, or wiring site. The codebase is unusually low-debt: **zero** `TODO/FIXME/XXX/HACK` markers and **zero** `raise NotImplementedError` in production code.
- **One HIGH security finding:** [`POST /api/v1/coverage/benchmarks/runs`](../fragchain/api/routers/coverage_benchmarks.py#L55) has no auth and spends LLM budget anonymously. The whole `coverage_benchmarks` router lacks the `require_authenticated`/`require_maintainer` dependency that comparable LLM-spending endpoints (`vector.py`, `rules.py`) carry.
- **One systematic schema drift:** six FKs into `coverage_assessment` from migration 0017 ship without an `ondelete` clause, but the ORM declares `ondelete="SET NULL"` — deleting an assessment will raise `ForeignKeyViolationError` despite the model contract. Three of those columns also declare `index=True` in the ORM but the migration never creates the index, which is a real query-performance regression on the active `?assessment_id=` filters.
- **One §19 audit-log gap on the active flow:** [`AssessmentService.close`](../fragchain/assessments/service.py#L118) writes no `audit_entity_state_change` row, even though it's the terminal `* → completed` transition on `coverage_assessment.state` — CLAUDE.md §19 makes this mandatory.
- **MEMORY.md carryover resolved:** the migration 0017 `superseded_at` backfill is shipped at [0017_assessment_centric.py:246-257](../fragchain/db/migrations/versions/0017_assessment_centric.py#L246), running before the partial unique index.
